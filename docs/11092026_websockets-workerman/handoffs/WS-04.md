## Important Context

- `NotificationService::sendToUser` despacha por `NotificationManager` (canales `database` + `realtime`). En `app` mode, el `RealtimeChannel` publica en el `LocalEventBus` inerte; la entrega real al cliente la hace el servidor Workerman por polling de la tabla `notifications`. Por tanto, `NotificationService` puede invocarse desde cualquier request HTTP y la notificación llega al cliente WebSocket conectado (vía polling del server).
- El frame WebSocket entregado por el polling es `{"event":"notification","data":{"id","type","title","message","data","created_at"}}` (spec §7).
- `realtime:restart` usa `start /B` en Windows y `nohup … &` en Linux para relanzar en background.
- `realtime:stop` limpia `runtime/realtime-delivery.json` además del pid file (HWM por instancia).

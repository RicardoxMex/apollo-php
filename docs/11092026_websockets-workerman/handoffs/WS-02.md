## Important Context

- El `Worker::$pidFile` se establece desde `websocket/server.php` y desde el CLI `realtime:start`. En Windows foreground Workerman no escribe el pid file automáticamente; el CLI lo escribe antes de `runAll()` con `writePid(getmypid())`. En Linux daemon, Workerman sobreescribe con el pid del proceso daemonizado.
- El bootstrap de la Application se hace en `onWorkerStart` (cada worker crea su propio container/PDO), evitando el problema de PDO forked en Linux daemon.
- En Windows, `worker->count` se fuerza a 1 (Workerman lo requiere). `-d` daemon se ignora en Windows con un warning.
- El polling (`WEBSOCKET_POLL_INTERVAL`, default 1s) consulta `notifications WHERE id > lastDeliveredId[user]` y entrega vía `ConnectionManager::sendToUser()`. El HWM se persiste en `runtime/realtime-delivery.json` (LOCK_EX). En reconexión, el usuario recibe las notificaciones perdidas automáticamente.
- El handshake WS real verificado: `Sec-WebSocket-Accept = base64(sha1($key . "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"))` lo calcula Workerman correctamente.
